# Задача для агента: довести UI «Биокомпаса» до уровня продукта

Ты работаешь в проекте **Биокомпас** — MVP-сервис подбора медицинских анализов.
Пользователь пишет свободным текстом, что хочет проверить («усталость, вес, щитовидка»),
а сервис находит позиции каталога лабораторий: название, цена, срок готовности,
ближайшая точка забора и объяснение «почему подходит».

Стек: ASP.NET Core Minimal API (`src/BiocompassAI.Api`), фронтенд — **один статический файл**
`src/BiocompassAI.Api/wwwroot/index.html` (без фреймворков и без CDN), тесты — xUnit.

## Что не так

Фронтенд технически рабочий, но выглядит как черновик: нет визуальной иерархии,
карточки результатов нечитаемы, непонятно, на что смотреть в первую очередь,
нет ощущения надёжности — а это медицинский сервис, где доверие и есть продукт.
Плюс нет подсказок: человек не понимает, что можно спросить и что делать, если ничего не нашлось.

## Что нужно сделать

1. **Прочитай скилл `ui-ux-pro-max`** (инструмент `read_skill`) и работай по нему,
   а не «на глаз»: сначала общее направление (стиль, палитра, типографика), затем
   точечные правила по UX, которые нужны этой странице.
   Скилл подключён как текст `SKILL.md`: его вспомогательные файлы (`references/`, `scripts/`)
   недоступны, и запускать `search.py` не нужно — работай по правилам из `SKILL.md`
   и своему знанию UX. Не трать шаги на поиск этих файлов в рабочей папке.

2. **Переделай `wwwroot/index.html`** так, чтобы страница выглядела как продукт, а не как демо:
   шапка и первый экран, поиск, состояние загрузки, результаты, пустой результат,
   уточняющий вопрос, внешние источники, дисклеймер.

3. **Не ломай и не выдумывай контракт.** Источник истины — код API:
   `src/BiocompassAI.Api/Contracts/SearchContracts.cs` и `src/BiocompassAI.Api/Endpoints/ApiEndpoints.cs`.
   Сверься с ними до правок: фронтенд сейчас может расходиться с бэкендом — если так,
   приведи UI в соответствие с фактическим контрактом (это часть задачи) и напиши, где было расхождение.
   Эндпоинты (`POST /api/search`, `POST /api/search/{id}/click`) менять не нужно.
   Никаких новых зависимостей, сборщиков и внешних CDN — файл должен открываться как есть.

4. **Доступность и адаптивность.** Контраст текста не ниже 4.5:1 в обеих темах
   (`prefers-color-scheme`), видимый фокус с клавиатуры, кликабельные элементы не мельче 44×44 px,
   `aria-live` для статуса, `prefers-reduced-motion` учитывается, ничего не разъезжается на 375 px.

5. **Проверь результат сам**, не на словах:
   - `dotnet build src/BiocompassAI.Api` — должно собраться;
   - `dotnet test tests/BiocompassAI.Tests` — тесты должны остаться зелёными;
   - открой получившуюся страницу (headless-браузер или проверка разметки) и убедись,
     что все состояния рендерятся: пустой список, загрузка, карточки, ошибка сети.

В конце коротко отчитайся: что изменил, какие правила скилла применил и чем подтвердил,
что страница работает. Не пиши «готово», если сборка или тесты не запускались.
