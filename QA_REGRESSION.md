# QA: регрессионные сценарии для агента и чата

Здесь описаны сценарии, которые уже ломались в проде. Прогонять их перед каждым релизом,
затрагивающим агентский раннер, историю чата или SignalR.

---

## 1. Контекст внутри одной сессии (ломается повторно)

**Почему этот сценарий обязателен:** история для агента (`ConexyAgentRunner`) уже собиралась
неправильно дважды — сначала она вообще не передавалась, затем не записывалась для прерванных
ходов. Поэтому проверять нужно не «одно сообщение», а цепочку из трёх.

1. Открыть вкладку **Агент**, дать короткую задачу (например «объясни, что делает этот файл»).
2. Дождаться **самостоятельного** завершения (без нажатия «Стоп»).
3. Вторым сообщением написать: «покороче, без воды». Агент должен укоротить **свой предыдущий
   ответ**, а не спрашивать «что нужно сделать?».
4. Третьим сообщением: «а теперь то же самое списком». Агент должен по-прежнему понимать, о чём речь.
5. Повторить пункты 1–4, но на шаге 2 **прервать** генерацию кнопкой «Стоп», затем задать
   follow-up вопрос. Контекст первого ответа должен сохраниться.

**Что смотреть в логах бэкенда** (уровень Information):

```
Agent context: task=<taskId> chat=<chatId> user=<userId> historyRows=<N> attached=<M> roles=[user,assistant,...]
Agent context tail: task=<taskId> role=assistant preview="..."
```

- `attached=0` при непустом диалоге → история не читается (проверить `chatId`/`userId`).
- `attached>0`, но агент всё равно «не помнит» → проблема не в передаче контекста, смотреть промпт.

**Известные ловушки (уже исправлены, не регрессировать):**

- Агентский путь должен **читать** историю (`_chatHistory.GetMessagesAsync`) и **писать** её
  (`PersistTurnAsync`).
- Прерванный ход (стоп / ошибка) тоже должен попадать в историю — иначе следующее сообщение
  приходит без контекста. См. `PersistInterruptedTurnAsync`.
- Рабочая область разговора **не должна** удаляться при остановке/ошибке — иначе агент видит
  пустую папку и отвечает «файлов нет».

## 2. Генерация завершается сама

1. Короткая задача в любом режиме (flash, pro, агент): текст на 3–5 предложений без команд.
2. После последнего токена сообщение должно перейти в завершённое состояние **не позже чем за
   2–3 секунды**, статус-бар — в «Завершено». Кнопка «Стоп» должна смениться на отправку.
3. Повторить на длинной агентской задаче с командами: финальный текст тоже должен закрыть turn сам.

**Что смотреть в логах бэкенда:**

```
Task <taskId> finished; broadcasting OnCompleted (<N> chars of result).
Agent iteration <step>/<max> task=<taskId> toolCalls=<k> contentChars=<n> ...
```

- `Agent iteration` растёт, а `contentChars` остаётся маленьким → агент зациклился; проверить
  `Agent:MaxIterations` и промпт.
- Есть `finished; broadcasting OnCompleted`, а UI всё ещё «думает» → проблема на клиенте, смотреть
  консоль браузера (`[Resync] turn finalized from server state`).

---

## 3. Устойчивость соединения

1. Долгая задача (5+ минут), вкладку не трогать — соединение не должно рваться.
2. Во время работы вручную прокрутить ленту вверх — автоскролл прекращается, появляется кнопка «вниз».
3. Обновить страницу посреди задачи — статус подхватывается с сервера (кнопка «Стоп» не висит вечно,
   карточки команд показывают актуальный статус).
4. Проверить баннер соединения: при обрыве — «Соединение потеряно, пытаемся переподключиться…»,
   через минуту — сообщение с кнопкой «Обновить страницу».

Логи бэкенда, подтверждающие причину разрыва:

```
SignalR connected: <connId> user=<userId> path=<path>
SignalR disconnected: <connId> with error: <...>   (или "(graceful)")
```
